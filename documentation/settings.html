Settings

What is on the Settings page, how to configure the server, and what to do when something goes wrong.

Settings sections

Open Settings in the sidebar.

Connections

Tool servers (MCP servers) for every agent on this machine, in every CLI installed here.

  • Built into the orchestrator: signal, which you connect once.
  • Your servers: servers you added. Check tests one. A small tag shows which CLI has it.
  • Add a server: enter a name, an address and an optional token. Test tries it without saving. Add tests first and writes nothing if the server refuses.

Media tools

Agents can edit video and audio by running commands such as ffmpeg in their own terminal. This page shows which of those commands are installed on the machine: ffmpeg, ffprobe and ImageMagick are the main ones; yt-dlp, SoX and ExifTool are optional. Nothing here ships with the app. If a main one is missing, a red dot appears on Settings. Install it, then press Re-check. You can ignore this page if your agents do not touch media.

Performance

CPU and memory for the computer, the orchestrator and this page, plus a table of each agent's processes. It also gives plain advice, such as closing terminals you are not using. Each open terminal is a whole CLI program, so they add up.

Removed agents

Unregister takes an agent off the canvas but keeps its runs, messages and transcript. This page deletes those for good, one at a time or with Delete all. What the agent sent, its playbook file in the project folder, and what you typed in the CLI's own history stay.

General

The theme: Auto follows your computer, or choose Light or Dark. The theme button at the bottom of the sidebar cycles through them.

The .env file

Put settings in a file named .env next to session_orchestrator.py (or next to agent-orch.exe), one NAME=value per line, then restart the server.

Security warning

Agents run shell commands with permissions bypassed, and there is no API key. Anyone who can reach the dashboard can make your agents do anything on your computer. ORCH_HOST=0.0.0.0 hands that to everyone on your network.

By default the server listens on your own machine only and refuses requests from other websites. It prints a warning at startup if you open it up. Run it as your own user, never as root, and give agents only projects you are happy for them to change.

Keep it running

This is optional. Replace the paths with where you unzipped or cloned it.

Windows: Task Scheduler 
$exe = "$HOME\agent-orch-windows-x64\agent-orch.exe"
Register-ScheduledTask -TaskName "AgentOrchestrator" `
  -Action  (New-ScheduledTaskAction -Execute $exe -WorkingDirectory (Split-Path $exe)) `
  -Trigger (New-ScheduledTaskTrigger -AtLogOn) `
  -Settings (New-ScheduledTaskSettingsSet -StartWhenAvailable `
               -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1))

Remove it with Unregister-ScheduledTask -TaskName "AgentOrchestrator".

macOS: launchd 
cat > ~/Library/LaunchAgents/com.agent-orch.plist <<PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.agent-orch</string>
  <key>ProgramArguments</key><array>
    <string>$HOME/unity-agent-orchestrator/.venv/bin/python</string>
    <string>$HOME/unity-agent-orchestrator/session_orchestrator.py</string>
    <string>serve</string>
  </array>
  <key>WorkingDirectory</key><string>$HOME/unity-agent-orchestrator</string>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>$HOME/Library/Logs/agent-orch.log</string>
  <key>StandardErrorPath</key><string>$HOME/Library/Logs/agent-orch.err</string>
</dict></plist>
PLIST

launchctl load -w ~/Library/LaunchAgents/com.agent-orch.plist

Stop it with launchctl unload -w ~/Library/LaunchAgents/com.agent-orch.plist.

Linux: systemd user service 
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/orchestrator.service <<'UNIT'
[Unit]
Description=Agent Orchestrator
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/unity-agent-orchestrator
ExecStart=%h/unity-agent-orchestrator/.venv/bin/python %h/unity-agent-orchestrator/session_orchestrator.py serve
Environment=PYTHONUNBUFFERED=1
Restart=on-failure
RestartSec=3
TimeoutStopSec=15

[Install]
WantedBy=default.target
UNIT

systemctl --user daemon-reload
systemctl --user enable --now orchestrator
loginctl enable-linger "$USER"     # start at boot, not only when you log in

Logs: journalctl --user -u orchestrator -f.

Updating

  • From source: run git pull, then pip install -r requirements.txt, then restart.
  • Prebuilt: download the new zip and replace the folder, keeping your .env.

See what changed in the changelog.

Troubleshooting

What you seeWhat to do
The dashboard does not open, or the server says the port is in useSet ORCH_PORT in .env and open that port instead.
Windows SmartScreen flags the downloadThe builds are not code-signed. Compare the hash with SHA256SUMS.txt from the release, then run Unblock-File on the zip.
macOS: the install fails on a Python versionUse Homebrew's python3.12, as in the macOS steps.
An agent cannot find send_signal or spawn_subagentPress Connect next to signal in Connections, then press reload on the card.
A CLI is not foundSet CLAUDE_BIN or ORCH_AGY_BIN to its full path. Also check you are logged in to that CLI.
A terminal shows disconnected — press 🔄 to reloadPress the reload button on the card's left edge.
A card shows The automatic run finishedThat is normal. Press reload to load the new context and keep chatting.
Create agent says Pick a model or Pick a workspaceEach field is required. New workspace on Home makes one if you have none.
A sub-agent card says no worktreeThe director's folder is not a git repository, so the sub-agent shared it. Run git init and make a first commit, or point the director at a repository.
A message sits there and nothing runsCheck whether the agent is paused, the workspace is suspended, or it is waiting for approval. See how to stop things.
A message shows blockedA run or token limit was reached. Press Allow + in the agent's panel if it is the daily limit, or raise the limit in .env.
Reflect fails with a read-only sub-agent changed filesThe read-only agent really changed files. Nothing was undone. Check them with git status.
The computer feels slowOpen Performance. It names what is using the machine.

The server's health and API docs are at /health and /docs on the dashboard's address. If you are still stuck, report a bug.
